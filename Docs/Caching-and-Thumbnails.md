# 目錄、檔案與縮圖快取

## 0.4.11 已實作（macOS）

- 新使用者預設開啟讀取快取；保留既有使用者明確關閉的選擇。
- S3、WebDAV、Drime、SFTP 等一般掛載共用 VFS 快取政策；保險箱同樣採用全讀寫快取。
- 使用者可設定檔案快取容量、閒置保留時間、目錄清單有效時間（1–60 分鐘，預設 5）。
- 目錄清單只在掛載程序記憶體內快取，不是持久或完整離線索引。其他裝置的修改可能延遲至重新查詢才顯示。
- 每個檔案讀取緩衝降為 4 MiB、每程序緩衝池上限 64 MiB（不等於程序總記憶體上限）。
- 遠端讀取從 8 MiB 區塊開始，連續讀取逐步增大至 64 MiB；不額外啟動平行區塊串流，不設定額外預讀。
- 快取清理以保留 1 GiB 空間為目標；使用中或尚未上傳的資料不為清理而刪除。容量與可用空間均為盡力維持，並非硬上限。
- 保留完整變更指紋、修改時間與校驗；未啟用 fast fingerprint、no-modtime、no-checksum、S3 no-head。
- 不遞迴預載全部目錄或全部原圖，避免大量背景請求。
- 設定僅套用新掛載；既有掛載需安全卸載後重掛。保險箱需正常鎖定後重新解鎖。

## 三種不同層次

| 層次 | 快取內容 | 實際邊界 |
|---|---|---|
| 目錄 | 檔名與目錄項目 | 第一個成功的遠端清單請求仍然必要；逾時不能拿空目錄冒充成功 |
| 檔案 | 已經讀取的位元組範圍 | 部分快取不代表整個檔案離線可用；跨機修改仍要檢查 |
| 縮圖 | 降採樣後的小圖片 | macFUSE 掛載目前由 Finder / Quick Look 管理；CloudMount 尚未提供自有縮圖快取 |

Finder 首次產生縮圖可能讀取完整原圖，視格式與解碼器而定。部分格式可只讀部分位元組。VFS 快取減少重讀內容，不等於必然減少所有 S3 LIST / HEAD 請求，也不能保證系統一直保留縮圖。

## 建議後續實作

iOS / iPadOS 的 File Provider 可實作 `NSFileProviderThumbnailing`。macOS 的現有 macFUSE 掛載無法把任意自製 JPEG 縮圖直接交給 Finder；若要由 App 控制縮圖供應，需要新增 macOS File Provider 或 App 內瀏覽器。這是獨立工程，不是更改一個 rclone 參數。

建議縮圖服務設計：

1. 有原生縮圖 API 的服務先向服務取小圖；S3 / WebDAV / FTP / SFTP 通常沒有通用縮圖 API。沒有縮圖時才限量讀取原圖並降採樣。
2. 僅對畫面內或使用者選取的項目處理；網路與解碼各最多 2 件，同一請求合併，離開畫面即取消。不要為整個帳號建立縮圖。
3. 初版限制圖片原檔大小與解碼像素數，拒絕超大尺寸或可疑壓縮圖；大影片不在背景全檔下載。
4. 快取索引必須包含位置 ID、穩定項目 ID、遠端版本（ETag / 版本號 / 修改時間與大小）、縮圖尺寸與產生器版本；沒有可靠版本時採較短有效期。修改、覆寫、刪除時失效。
5. 普通縮圖採磁碟 LRU，例如每位置最多 256 MiB、總計 512 MiB，閒置 7 天清理；這些是建議值，目前未實作。
6. 加密保險箱縮圖須視為明文敏感資料：優先只放記憶體；若持久化，使用個別保險箱金鑰加密。鎖定時取消工作、清理記憶體、停止供應縮圖，未解鎖不能先取內容。
7. 系統自己產生或保留的 Quick Look、檔案預覽副本不能宣稱能完全抹除，必須在使用說明中說明範圍。
8. 網路離線、版本改變、取消與擴充程序中止均要完成回呼；縮圖失敗不標示整個遠端連線失效、不阻擋普通檔案讀寫。

## 2026-10-24 檢查結果

使用者回報的 S3 圖片目錄在只讀測試中，連清單回應標頭都發生逾時；上層目錄約 0.6 秒完成。對照原修改時間 / 不讀修改時間、HTTP/2 / HTTP/1.1、分頁 1000 / 100、新版 ListObjectsV2，均未消除該圖片目錄的逾時。這不是證明縮圖解碼慢；需另查 S3 gateway / 上游列目錄的耗時、請求排隊、分頁與快取。未更改遠端檔案，也沒有為此永久改變 S3 連線協議設定。
