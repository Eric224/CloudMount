# Drime 直連：CloudMount Mobile（0.1.2 起）

## 使用方式

1. 在 CloudMount 點「新增雲端空間」，選 **Drime**。
2. 點「開啟 Drime 建立權杖」，在 Drime 設定的 **開發者 / Developers** 建立個人存取權杖。授予 **Files、Folders 讀寫權限**，貼回 CloudMount。不是網站密碼，也不需要把權杖交給開發者。
3. 點「連接並加入『檔案』」。系統若要求啟用位置，到「檔案 → 瀏覽 → … → 編輯」開啟 CloudMount 對應位置。
4. 普通檔案可直接瀏覽與編輯。要加密，回 CloudMount 的「加密保險庫」建立新保險庫，或選「加入現有保險庫」，選擇 Mac 保險庫所在資料夾並搜尋，輸入相同密碼。
5. 在 CloudMount 解鎖一次後，再從「檔案」使用。可選擇在此裝置記住密碼。這版請從主 App 解鎖／上鎖；Files 內自動密碼介面仍待真機驗證。

不需要 Mac 開機，手機／平板直接連 Drime API。桌面 rclone 設定不會自動同步；連接同一帳號與同一資料夾即可讀取相同雲端資料。一般情況只填權杖，工作區 ID 與起始資料夾 ID 收在進階設定。

移除空間僅移除此裝置的連線、登入資料和 Files 入口，保留雲端檔案與保險庫。個人權杖可能也用在其他裝置，因此不會自動全域撤銷；建議每台裝置各建立一個權杖，可在 Drime 個別撤銷。更換權杖時會驗證帳號 ID；不接受悄悄切換到另一個帳號。

## 檔案與保險庫

- 原生列出／下載／新增／覆寫／改名／搬移／刪除檔案與資料夾，沿用 File Provider 的穩定本機 ID、待上傳紀錄與重試。
- 使用 CloudMount 共用的 **標準 Cryptomator v8 格式**，支援建立、搜尋／加入、解鎖／上鎖、44 詞復原金鑰、可還原的保險庫刪除與還原。與 Drime 自有的 Vault 功能不同，不會呼叫其專用 Vault API。
- 小檔採磁碟上的 multipart/form-data；5 MiB 以上採 Drime 分段上傳。以 1 MiB 緩衝串流分段暫存檔，記憶體不隨整個檔案增長。失敗的分段工作會記錄 session，在重試時清理自己建立的工作並重傳；中止失敗保留紀錄、顯示待清理狀態，最多累積 16 個未確認清理的工作後暫停新上傳。**尚無跨重啟逐段續傳**。
- 上傳到獨立隨機暫存名稱。優先用官方 verify-integrity 重新計算 SHA-256；舊服務或共用檔案無權使用該端點時才讀回驗證。一般改名／搬移使用伺服器 API，不重新上下載全部內容。
- 覆寫前檢查舊版本，保留原項目到專用備份名稱，確認新項目 ID／位置／大小後才清理舊版本。全部替換步驟寫入受保護的本機紀錄，中斷後可接續。不先刪原檔。
- 清理舊項目失敗不會把已確認完成的寫入判成失敗並重傳。主畫面顯示待清理數量，可重試；保留項目可能在 Drime 網站看到 `.cloudmount-previous-*`。刪除一律移入 Drime 垃圾桶，從不清空垃圾桶或永久刪除。
- 422 或任何本地化錯誤文字本身都不能證明刪除成功；只有完整新列表與該 ID 已刪除／不存在的 metadata 證據才承認完成。分頁不完整、重複名稱、錯誤父目錄、內容驗證不符均停止操作。
- Token 只在本裝置共用鑰匙圈；不進設定 JSON、URL、命令列或紀錄。API、簽名上傳 URL 使用不同請求，不將 Drime Token 送往儲存供應商；下載重新導向外部主機也移除 Token。HTTPS 憑證由系統驗證。

## 驗證與界線

本機的獨立 Python REST fixture 不含真實帳號，模擬分頁、Unicode、覆寫、搬移、刪除、422 已刪除／未刪除、遺失回覆、失敗後重新建立 adapter、分段失敗重試、SHA-256、跨主機重新導向及跨裝置保險庫流程。這證明本機流程，不代表正式 Drime 服務／真機已完成認證。

使用者要求暫緩真機測試：沒有啟動真機 App，也沒有新增／修改實際 Drime 文件。正式 Drime 的最新回覆、行動網路／背景中斷、Files 編輯器與 Mac 同時編輯，仍需後續授權測試。File Provider 舊版已知限制（例如同次改名加內容修改）仍適用，詳見 README。

Drime API 沒有為這套多步驟替換提供跨用戶端 compare-and-swap／交易保證。此版序列化同一裝置所有 Drime 操作、檢查版本並保留舊檔，但不能保證兩台裝置同時寫同一檔案的全域原子性。請避免同時編輯同一檔案；保險庫格式相容也不等於具備分散式鎖。

瀏覽器 OAuth 需要註冊 CloudMount 的 public client、HTTPS 回呼與關聯網域等設定；官方拒絕自訂 scheme 回呼。此版未假造 client ID、未內嵌共用 Token 或客戶端密鑰，採使用者自己的個人權杖。若對外發行，應完成正式 OAuth、授權範圍及產品審核，再宣稱一鍵登入。

官方參考：[API](https://docs.drime.cloud/introduction)、[個人權杖](https://docs.drime.cloud/authentication)、[OAuth](https://docs.drime.cloud/oauth/authorization-flow)、[rclone Drime](https://rclone.org/drime/)。
